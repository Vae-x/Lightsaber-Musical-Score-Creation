# AI 设置与自动制谱方案

v0.4.0 在已有连接设置基础上提供 AI 分析与整曲制谱。目标是音乐贴合、挥刀顺畅、段落有呼应与变化；生成结果先试听预览，应用后可继续编辑。v0.4.0 便携包包含这些功能；旧 v0.3.0 下载包保留原发布内容。

2026-10-04 源码开发版在此基础上增加默认的“本地快速制谱”，保留“大语言模型制谱”作为另一种生成方式。新增功能尚未打包到已发布的 v0.4.0 Release。

## 已实现的设置

- 设置集成在主窗口，左侧导航依次为曲谱编辑、AI 分析与制谱、外观、大语言模型、网络、关于；账号授权归入大语言模型子菜单。默认收起为 64 像素图标栏，可点击模型图标打开子菜单；展开为 208 像素文字导航时支持鼠标箭头和键盘左右展开、收起。主题支持浅色、深色与跟随 Windows 系统，切换同时更新放置网格、波形时间轴和轨道预览。
- 菜单“设置 → 外观设置”与 `Ctrl+,` 切换到外观页；切换页面保留设置草稿及曲谱、选中物件、播放位置。“应用”保存并留在当前设置页，“保存并返回”保存后回到曲谱编辑，“取消并返回”恢复最近成功保存的全部设置与主题后返回编辑。
- DeepSeek、Kimi、MiMo、OpenAI、通义千问及自定义 OpenAI 兼容提供商预设。各提供商配置独立保存；模型通过 `GET <API 地址>/models` 获取，保留手动输入与重新读取入口。API 请求使用 Bearer 鉴权，MiMo 同时使用其官方要求的 `api-key` 头。
- API Key 使用 Windows 当前账户 DPAPI 加密后原子保存到应用配置目录。歌曲文档、工程和游戏导出不携带密钥。
- Codex 账号方式通过本机官方 CLI 的 App Server 标准输入输出通信，完成初始化、账号读取、浏览器授权与 `model/list` 分页读取。账号令牌由 Codex 持有与续期；本程序不读取令牌文件。设置阶段不创建 Codex thread/turn。
- Windows 模型请求使用系统 WinHTTP 的 TLS、证书校验与代理支持，避免依赖 Qt 5.12 安装包缺失的 OpenSSL 运行库。请求可取消、有超时与大小限制，重定向不会携带密钥自动跳转。
- 网络代理默认自动，API 使用系统代理，Codex 自动沿用 CLI 的运行环境。另有手动 HTTP 代理与直连模式；手动地址和端口用于 API 及本程序启动的 Codex 子进程，本机服务保持直连。直连仅清除本程序子进程的代理环境，不修改系统或用户 CLI 配置。“检查代理端口”通过不代表模型服务已连通，还需获取模型或实际推理确认。
- 分析与制谱的单次模型推理默认十分钟，可在网络页设置为 1–30 分钟。账号连接及普通 CX 请求阶段使用一分钟连接时限；创建生成轮次及模型推理共用单次推理预算，避免另一个短计时器提前取消。API 模型列表读取继续使用其独立连接时限。
- 关于页可启用、查看和导出诊断日志，AI 页还可按本次任务筛选。日志记录任务/请求标识、阶段、耗时、连接与模型、代理模式、错误类别及 HTTP/RPC/Windows 错误码；不记录密钥、账号内容、登录链接、歌曲路径、提示词、模型全文或 CLI 原始输出。
- 帮助菜单的“关于光剑曲谱制作”切换到主窗口关于页，显示应用名称、版本、作者与项目主页，主页按钮调用默认浏览器；GPLv3 官方原文在关于页内展开、滚动阅读和收起。

来源：[DeepSeek 接入](https://api-docs.deepseek.com/zh-cn/)、[Kimi 接口](https://platform.kimi.com/docs/api/overview)、[MiMo 平台](https://platform.xiaomimimo.com/)、[通义千问兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[OpenAI 模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)、[Codex App Server](https://developers.openai.com/codex/app-server)、[Codex 开源实现](https://github.com/openai/codex/tree/main/codex-rs/app-server)。提供商模型名称动态读取，列表存在不代表该模型一定适合对话或制谱。

## 使用流程

1. 歌曲解码完成后进入“AI 分析与制谱”，开发版默认选择“本地快速制谱”，无需模型连接。选择“大语言模型制谱”时，先在“大语言模型”或其“账号授权”子菜单保存连接与模型。
2. 可先分析音乐；新歌整曲生成前选择简单、普通、困难、专家或专家+，并勾选允许出现的方向方块、无方向方块、炸弹、墙。默认仅方向方块；只选择炸弹或墙时可生成避障练习谱。选择某类不强制填满该类物件。
3. 使用曲谱编辑中已确认的 BPM 与第一拍。本地方式显示音乐特征提取和动作搜索进度；模型方式另有整曲规划、分段生成及返修进度。任务可取消；切换到编辑或设置页后任务继续，返回 AI 页仍保留进度、分析与候选谱。
4. 完成后在独立时间轴和三维轨道中试听候选谱，检查难度、密度、物件数量及提示。预览不会改变工程；关闭预览后可用“查看候选谱”再次打开。其他页完成时只提示，返回 AI 页后手动查看。本地方式在音源修订、PCM 文件状态、时间参数和拍格一致时复用分析；模型方式在相同音源、时间参数、难度、类型和模型下沿用已完成的分析规划。
5. 点击应用后保存到目标难度：已有同名难度仅替换该谱，否则添加新谱并保留其他难度；首次完全空白的单谱复用为第一个目标。预览说明新增或替换的范围，应用后选中目标。新歌按全歌操作顺序撤销、重做，新增难度也可一次撤销并恢复原选择；导入歌曲仍按当前谱撤销。工程、恢复快照和导出保留所有难度，开场缓冲同步处理每张谱及共享音频。

首版每次生成一张新歌 Standard 基础 v2.2 谱。既有歌曲可分析，生成应用入口不覆盖导入谱；高级关联保护、未知字段和原始资源的保存规则继续生效。生成不自动修改 BPM 或插入变速事件，开场缓冲仍只作用于导出副本。

## 本地编排（源码开发版）

`LocalAiGenerationService` 在单个后台线程运行，使用 `AudioService` 的只读 PCM 租约，不调用模型或访问网络。连续替换任务先中断旧线程，再启动最新请求；任务世代隔离晚到结果。缓存仅保留一份音乐分析，不持有音频租约；每次复用检查音源修订、PCM 路径/大小/修改时间、采样参数、时间映射和拍格。取消、结束和销毁释放工作任务持有的资源。

`LocalChartGenerator` 根据难度、段落能量和起音置信度选择击打锚点，从有限动作模式中搜索左右手、位置及切向组合，并考虑下一刀的衔接。搜索有固定候选与前瞻上限，重复段优先沿用已有主题，实际起音和手状态决定适配。炸弹与侧墙使用对应休息/边界锚点并避开击打；所有类型最终交给现有 `BeatmapPlayabilityValidator` 全曲检查。完整合格后才发布草稿，不自动写工程或设备。

本地生成使用当前确认的拍线，不自动改 BPM、第一拍或变速；分析误差和缺失起音仍会影响结果。动作库属于内置编排模板，尚无头显手感验收。相同输入的本地生成可复现，重新生成不承诺随机改变结果。未接入深度学习训练或预训练模型；不要求独立显卡，也不承诺所有硬件或歌曲的固定耗时。

两种方式沿用同样的新歌限制、未知字段与高级关联保护、预览、原子应用、多难度保存和撤销。切换生成方式取消任务并清空候选；模型连接设置变化只影响模型方式。下面的网络额度、返修、恢复和续跑说明均针对大语言模型方式。

## 大语言模型编排

`MusicFeatureAnalyzer` 在后台流式读取完整原速 s16le PCM，提取起音、频段能量、静音、段落变化和重复候选，首版音频分析上限为一小时。短鼓点之间的间隙并入连续音乐活动区间，真正长静音不计入活跃时长。`AudioService::pcmSnapshot()` 提供共享只读租约，分析期间切歌也不会提前回收旧缓存。起音映射到当前 `TimeMap` 下的允许拍格；击打、休息和边界位置有独立锚点 ID。

`AiGenerationService` 先请求真实模型规划整曲，再顺序生成乐句。每段携带上一段已验证的物件、两只手末状态、后续音乐提示及重复动作主题。模型决定采用哪些锚点、左右手、格位与切向；程序将锚点 ID 转换成拍数，模型不能任意改写时间映射。重复段落参考已通过的主题，并按音乐进行适度变化。

重复音乐以各组固定首段为基准，选择相似度最高且满足能量和长度要求的组，避免通过中间段逐步误归组。规划和乐句请求均提供重复置信度与参考段；主题请求另外提供实际动作参考。动作主题按拍序、同拍按左右手排序，比较左右手与切向序列的最长公共子序列，差异为 `1 − 匹配数 / 两段较少的音符数`。相对拍上的节奏覆盖、匹配动作的位置变化及音符数量差分别记录，适应当前起音的移拍、减块和安全格位变化不会混入动作序列差异；任一段无击打时跳过主题比较。

`BeatmapPlayabilityValidator` 独立检查允许类型、锚点、网格、重复物件、真实秒数下的密度、同手间隔、出刀到入刀的回位距离、双手路径及障碍物冲突。180 度上下交替可自然顺接；同位置连续同向需要回位，无方向方块也须满足移动约束。炸弹避开挥刀与移动路径；首版墙仅使用单列侧墙，在休息段保留通行空间。

| 难度 | 活跃段目标 NPS | 连续两秒峰值上限 | 同手最短间隔 | 最细拍格 |
|---|---:|---:|---:|---:|
| 简单 | 0.8–1.4 | 2.5 | 450 ms | 1 拍 |
| 普通 | 1.3–2.0 | 3.5 | 330 ms | 1/2 拍 |
| 困难 | 2.0–3.0 | 5 | 250 ms | 1/2 拍 |
| 专家 | 3.0–4.2 | 6.5 | 200 ms | 1/4 拍 |
| 专家+ | 4.0–5.5 | 8 | 160 ms | 1/4 拍 |

NPS 只统计可击打方块，双块计两个；目标密度是软目标，音乐证据少时允许减少。以上是工程初值，不代表两游戏官方难度或已经实测的手感。

规划最多返修一次，每段最多两次，全任务最多十次返修，主题和硬校验返修共用预算。主题一致性是质量目标：每次通过硬校验后保留当前段动作差异最小的候选，同分保留较早者；返修耗尽后重新检查该候选的硬约束，合格则带提示继续编排。后续返修返回无效 JSON 或不合法物件也不会清除此前合格候选。提示包含乐句编号、时间范围、实际差异和目标，显示在结果页和候选预览；最终整曲仍必须通过硬校验才可应用。没有合格候选时显示失败，未完成整曲不能应用。程序不会补规则谱或制造起音；连续工作达到 45 分钟后暂停并保留进度，可手动继续。

网络、超时及 HTTP 500/502/503/504 等明确暂时性服务故障会有限自动恢复，同一规划或乐句最多两次、整任务最多十次，与校验返修预算分别计算；网络恢复按 2 秒、5 秒退避。截断仅在输出额度确实增长时自动重试。恢复期间保持 Running 状态，连续任务计时保持累计，保留已校验乐句、规划、主题与两手状态、最佳合格候选和返修反馈。恢复耗尽时保留进度供手动继续；全任务自动恢复次数和校验返修次数均不因手动继续重置。认证、权限、额度、参数、TLS 或协议问题按原因暂停，不自行重发。CX 的 `willRetry: true` 表示官方服务仍在恢复同一轮请求，客户端继续等待；明确终止的网络或服务故障才由应用重新请求。

每个 API 提供商独立保存 `maxOutputTokens`，`0` 表示自动，手动范围 1024–131072。只有官方 HTTPS 地址与已验证模型 `deepseek-flash` / `deepseek-v4-pro` 同时匹配时，采用 65536 起始额度、131072 上限及 `response_format=json_object`；不修改默认思考。截断后翻倍至上限，任务后续请求沿用增长后的额度；自动恢复次数耗尽后，手动继续也会在上限内提高已指定额度的截断请求，保持两类累计次数。手动上限覆盖自动上限，初始值取模型初始额度与上限的较小者；未知模型手动初始值为 8192，自动模式省略额度参数，截断后提示填写支持的上限。OpenAI 使用 `max_completion_tokens`，其他兼容接口使用 `max_tokens`。CX 不发送输出额度参数。规划提示词只规划主题与段落并要求简短文字，乐句提示词提供具体动作及硬约束；模型 JSON 协议与本地校验保持兼容。

保存范围为同一次程序运行，关闭程序后不恢复任务。切歌、修改曲谱/BPM/第一拍/音频/生成选项，或更换连接提供商、地址、模型后旧任务和结果失效。修改密钥、代理、超时时限或输出额度会停止在途请求及待执行恢复，但保留符合原模型和来源条件的进度；继续时读取新额度策略。主题、导航及临时忙碌状态保留结果。晚到响应不会覆盖新任务。

诊断日志位于 Qt 用户本地应用数据目录的 `logs/` 下，通过“关于 → 打开日志目录”定位。默认开启，按文件最近写入时间清理七天前的记录，每个文件最多 5 MiB、最多五个文件。导出仍进行字段过滤，并要求新的文件名。日志不可写时仅在查看界面提示，不中止制谱；关闭记录后仍可查看此前日志。

主题质量记录包含参考段、重复置信度、参考及当前音符数、匹配动作数、动作差异、节奏覆盖、位置变化、数量差、目标值，以及返修、接受或带提示接受的处理结果。主题质量与硬校验使用不同类别；候选、差异明细数组和提示词只保留在请求上下文，不写入日志。

恢复记录包含原因、当前乐句、局部与任务累计次数、退避时间、前后额度。完成及失败记录包含已应用额度、输入和输出用量、服务报告的思考用量、最终文本 UTF-8 字节数；未报告数值为 -1，API 请求省略额度记为 0，CX 额度为 -1。只记录白名单字段，思考正文与最终文本不写入日志。DeepSeek 额度及思考字段依据 [官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)，缺少思考用量不能推断输出全部用于思考。

## 推理通道与开发接口

- `ConfiguredAiTextTransport` 使用已有连接设置。API 通道调用非流式 `POST <API 地址>/chat/completions`，响应须有完整文本；本地统一校验 JSON，截断与工具调用不作为结果。Windows 继续使用系统 WinHTTP，无新增 Python 或 OpenSSL 依赖。
- CX 通道按本机官方 Codex 0.147.0 的 app-server 协议实现：复用既有登录，使用独立临时工作目录、短期线程与结构化输出。子进程禁用命令执行和外部集成，在只读/拒绝审批策略下运行，用户 MCP 逐个禁用；客户端拒绝并终止工具请求或工具事件。模型只处理传入的音乐特征，工程由本地程序应用。
- 请求固定文档实例、单调修订号、音频修订、时间映射、目标难度与类型选项；取消、超时和设置变化后的晚到响应不会替换新任务。
- `GenerationRequest` / `GenerationDraft` 与生成服务不持有编辑文档。主窗口核对来源后调用 `BeatmapDocument::applyGeneratedChart()`，一次原子提交物件和难度；失败不改变文档或撤销历史。
- 既有 `AiRecognitionService` 与 `MainWindow::setAiRecognitionService()` 继续保留供分析建议后端注入。新增 `MainWindow::setAiGenerationService()` 用于生成后端注入和模拟测试，调用方保持所有权。

原始音频和本地路径留在电脑，模型接收特征、时间锚点与动作上下文。文本模型给出的情绪或段落名称属于基于特征的编排建议。

协议来源：[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Codex App Server](https://learn.chatgpt.com/docs/app-server)。
