# Qt5 工程目录说明

这套目录参考 Qt5 桌面项目的源码分层方式，供后续放入源码和资源使用。

## 源码放置规则

| 目录 | 放什么 | 示例 |
| --- | --- | --- |
| `src/app/` | 程序入口、启动初始化、模块组装 | `main.cpp`、启动配置 |
| `src/core/` | 曲谱数据模型、拍数/时间换算、编辑规则、工程与音频服务 | `BeatmapDocument.h/.cpp`、`TimeMap.h/.cpp`、`AudioService.h/.cpp` |
| `src/gui/` | Qt 窗口、控件、图形视图及其 `.ui` 文件 | `MainWindow.h/.cpp/.ui`、`EditorViews.h/.cpp` |
| `resources/` | 图标、图片、样式、翻译和资源清单 | `.png`、`.svg`、`.qss`、`.ts`、`.qrc` |
| `tests/` | 自动化测试和用于测试的小型自建数据 | QtTest 测试源码 |
| `third_party/` | 第三方库的源码、构建配置、版本说明和许可证 | 音频或 ZIP 库 |
| `scripts/` | 编译、打包、部署和开发辅助脚本 | Windows 部署脚本 |
| `docs/` | 需求、架构、操作说明和历史讨论 | 交接说明、聊天记录 |
| `samples/beatmaps/` | 本地 BeatSaver 曲谱样本 | 已有十个 ZIP |
| `dist/` | 本机便携交付目录和 ZIP，不提交 Git | `Lightsaber Musical Score Creation*/` |

**核心源码的实际位置是项目根目录下的 `src/core/`。**

同一个 C++ 类的 `.h` 和 `.cpp` 放在同一目录。窗口类对应的 `.ui` 也放在该窗口类旁边。源码较多时，再按具体功能在对应目录下建立子目录，例如 `src/core/beatmap/`；当前保留简单的三层源码目录。

当前已有源码为：

```text
src/
├── app/main.cpp
├── core/
│   ├── BeatmapDocument.h/.cpp
│   ├── TimeMap.h/.cpp
│   ├── ProjectStore.h/.cpp
│   ├── AudioService.h/.cpp
│   └── RhythmAnalyzer.h/.cpp
├── gui/
│   ├── MainWindow.h
│   ├── MainWindow.cpp
│   ├── MainWindow.ui
│   └── EditorViews.h/.cpp
└── CMakeLists.txt
```

核心逻辑可以使用 QtCore 的类型，但应避免直接依赖窗口和界面控件；音频服务另外使用 QtMultimedia。`BeatmapDocument` 提供格式读取、保护检查、基础编辑和撤销重做接口，`ProjectStore` 提供资源与文件存储，`TimeMap` 处理分段 BPM 和秒拍换算。`AudioService` 使用 QProcess 调用随包工具，并使用磁盘 PCM 和 QAudioOutput 试听；`RhythmAnalyzer` 在后台分析估计节奏。界面调用这些核心接口；`src/app/` 是应用入口。

用户已经整体确认 [首版需求与架构](首版需求与架构.md)。业务类与工作台已实现，本机 Windows 11 的 Debug/Release 构建、五项 CTest、已有谱桌面编辑闭环、MP3/MP4 新歌流程和便携运行验证均通过；头显与 Windows 10 待实测。首版将格式读写和编辑命令集中在 `BeatmapDocument` 内，后续规模增长时再拆出独立类；计划中的 `BeatmapCodec`、`EditCommand` 和 `AppController` 不应误写为当前已有文件。未来自动制谱引擎保留独立任务/进程边界，具体引擎选型在后续评估。

## 构建文件与输出

项目使用 CMake，主构建文件为根目录的 `CMakeLists.txt`，通过 `add_subdirectory(src)` 加载源码模块。`src/CMakeLists.txt` 定义可执行目标 `src`、源码清单、Qt 模块和 Windows 运行库部署。

在 CLion 中可打开根目录的 `CMakeLists.txt`；为兼容目前已建立的 CLion 工程，`src/CMakeLists.txt` 也支持单独打开。编译器和 Qt 配置使用相应 CLion 工具链及 CMake 参数。

本次整理时检测到的工具为 Qt 5.12.12，qmake 位于 `F:/Qt/Qt5.12.12/5.12.12/mingw73_32/bin/`。这只是当前机器的工具信息，项目未固定为该版本或该架构。

当前已包含 Qt Widgets 主窗口、编辑画布与核心业务源码。新增类时，在 `src/CMakeLists.txt` 的对应目标源码清单中列出 `.cpp` 和 `.h`，例如 `core/BeatmapDocument.cpp` 和 `core/BeatmapDocument.h`。

源码目录已添加到目标的头文件搜索路径，因此入口可以使用 `#include "gui/MainWindow.h"`，界面可以使用 `#include "core/BeatmapDocument.h"`。

`third_party/ffmpeg/bin/` 是已准备的本地音频工具，不提交 EXE/DLL。版本来源与许可证随仓库保存；开发者可用 `scripts/setup-audio-tools.ps1` 下载固定构建并校验。便携部署时将工具及其说明/许可证复制到可执行文件旁的 `tools/ffmpeg/`。当前工具要求 Windows 64 位，不等同于 Qt 应用本身的 32 位架构。

`scripts/package-portable.ps1` 将 Release 应用、Qt 运行库与声音插件、音频工具和许可说明打包到 `dist/Lightsaber Musical Score Creation*/`，入口重命名为 `LightsaberMusicalScoreCreation.exe`；完整目录另压缩为 Windows ZIP 交付。当前交付是 `dist/Lightsaber-Musical-Score-Creation-Windows-20261001.zip`。Debug 构建仅用于开发，便携交付使用 Release。

测试源码包含 `tests/core_tests.cpp`、`AudioServiceTest.cpp` 和 `MainWindowTest.cpp`。测试媒体由 `GenerateAudioFixtures.ps1` 自建，用户曲谱样本留在本地。核心测试检查原样导出、修改合并、保护、恢复与 ZIP 路径；音频测试需要有效声音设备；界面测试使用真实控件事件和轨道画面断言。

编译输出使用独立的 `build/` 或 Qt Creator 的构建目录，不放进源码目录。`build/`、Qt Creator 用户配置和本地环境文件已由 `.gitignore` 排除。

空目录中的 `.gitkeep` 用于让 Git 保留目录；加入真实文件后可以移除该占位文件。

## 资料迁移

- 根目录的 `CX交接说明.md` 和 `聊天记录.md` 移至 `docs/`，原始内容保持不变。
- 根目录的 `music/` 移至 `samples/beatmaps/`，原曲谱包保持不变。
- 曲谱 ZIP 不提交 Git；仓库只保存样本目录的占位文件。克隆仓库后，可将本地曲谱放入该位置。
