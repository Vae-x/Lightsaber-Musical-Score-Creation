# Qt5 工程目录说明

这套目录参考 Qt5 桌面项目的源码分层方式，供后续放入源码和资源使用。

## 源码放置规则

| 目录 | 放什么 | 示例 |
| --- | --- | --- |
| `src/app/` | 程序入口、启动初始化、模块组装 | `main.cpp`、启动配置 |
| `src/core/` | 曲谱数据模型、时间换算、编辑规则、工程、音频、导出与连接配置 | `BeatmapDocument.h/.cpp`、`SongExporter.h/.cpp`、`AppSettings.h/.cpp` |
| `src/gui/` | Qt 窗口、控件、图形视图及其 `.ui` 文件 | `MainWindow.h/.cpp/.ui`、`EditorViews.h/.cpp` |
| `resources/` | 图标、图片、样式、翻译和资源清单 | `.png`、`.svg`、`.qss`、`.ts`、`.qrc` |
| `tests/` | 自动化测试和用于测试的小型自建数据 | QtTest 测试源码 |
| `third_party/` | 第三方库的源码、构建配置、版本说明和许可证 | 音频或 ZIP 库 |
| `scripts/` | 编译、打包、部署和开发辅助脚本 | Windows 部署脚本 |
| `docs/` | 当前需求、架构与操作说明 | `首版需求与架构.md`、`使用说明.md` |
| `samples/beatmaps/` | 本地 BeatSaver 曲谱样本 | 已有十个 ZIP |
| `projects/` | 本地自包含编辑工程，不提交内容 | `<歌名>/project.lmsc`、`assets-*`、`source-*` |
| `build/` | 构建和验证输出，不提交 Git | `debug/`、`release/`、`archive/` |
| `dist/` | 本机便携交付目录和 ZIP，不提交 Git | 完整 Windows 便携包 |

**核心源码的实际位置是项目根目录下的 `src/core/`。**

同一个 C++ 类的 `.h` 和 `.cpp` 放在同一目录。窗口类对应的 `.ui` 也放在该窗口类旁边。源码较多时，再按具体功能在对应目录下建立子目录，例如 `src/core/beatmap/`；当前保留简单的三层源码目录。

核心逻辑可以使用 QtCore 的类型，但应避免直接依赖窗口和界面控件；音频服务另外使用 QtMultimedia，连接使用网络接口。`BeatmapDocument` 提供格式读取、保护检查、基础编辑及原子生成应用/撤销，`ProjectStore` 提供资源与文件存储，`TimeMap` 处理分段 BPM 和秒拍换算。`AudioService` 使用随包 FFmpeg、磁盘 PCM 和 QAudioOutput 试听，生成任务通过 PCM 租约保留原速音频；`RhythmAnalyzer` 估计新歌节奏。`MusicFeatureAnalyzer` 分析全曲特征，`AiTextTransport` / `CodexTextSession` 统一 API 与 CX 推理，`AiGenerationService` 规划和分段生成，`BeatmapPlayabilityValidator` 检查动作与格式。`SongExporter` 在新歌导出时同步添加音频静音和物件开场缓冲，保持工程编辑时间不变；导入歌曲沿用原样导出规则。`MtpImportService` 只读枚举和复制两游戏的 PICO 歌曲，`WorkspacePaths` 选择可写的默认工程位置。`AppSettings` 保存主题、服务与代理配置，现有模型与账号设置接口继续提供；`AiRecognitionService` 保留分析建议注入契约。界面调用核心接口，独立 `GenerationPreviewDialog` 试听候选谱；`src/app/` 是应用入口。

用户已经整体确认 [首版需求与架构](首版需求与架构.md)。v0.3.0 包含新歌难度选择、对应导出文件名、默认 2 秒开场缓冲、双游戏导入，以及主窗口主题、AI 连接与网络配置。v0.4.0 包含 AI 分析、整曲生成、预览应用及分类导入导出；此前发布包保持原内容。用户已反馈此前版本导出的歌曲可在 PICO Neo 3 的《星穹绿洲》和《光之乐团》正常游玩，开场缓冲效果、自动生成谱手感、星穹绿洲分类识别与 Windows 10 兼容仍待分别实测。

2026-10-01 的 v0.2.0 本机验证记录为：Windows 11 Debug/Release、七项 CTest、界面 10 项 QtTest 与便携运行验证通过，包含真实 Neo 3 导入对话框。该记录保留为当时的验证事实，新功能测试应分别记录。格式读写和编辑命令仍集中在 `BeatmapDocument` 内，后续规模增长时再拆出独立类；计划中的 `BeatmapCodec`、`EditCommand` 和 `AppController` 不应误写为当前已有文件。

## 构建文件与输出

项目使用 CMake，主构建文件为根目录的 `CMakeLists.txt`，通过 `add_subdirectory(src)` 加载源码模块。`src/CMakeLists.txt` 定义可执行目标 `src`、源码清单、Qt 模块和 Windows 运行库部署。

在 CLion 中可打开根目录的 `CMakeLists.txt`；为兼容目前已建立的 CLion 工程，`src/CMakeLists.txt` 也支持单独打开。编译器和 Qt 配置使用相应 CLion 工具链及 CMake 参数。

本次整理时检测到的工具为 Qt 5.12.12，qmake 位于 `F:/Qt/Qt5.12.12/5.12.12/mingw73_32/bin/`。这只是当前机器的工具信息，项目未固定为该版本或该架构。

当前已包含 Qt Widgets 主窗口、编辑画布与核心业务源码。新增类时，在 `src/CMakeLists.txt` 的对应目标源码清单中列出 `.cpp` 和 `.h`，例如 `core/BeatmapDocument.cpp` 和 `core/BeatmapDocument.h`。

源码目录已添加到目标的头文件搜索路径，因此入口可以使用 `#include "gui/MainWindow.h"`，界面可以使用 `#include "core/BeatmapDocument.h"`。

`third_party/ffmpeg/bin/` 是已准备的本地音频工具，不提交 EXE/DLL。版本来源与许可证随仓库保存；开发者可用 `scripts/setup-audio-tools.ps1` 下载固定构建并校验。便携部署时将工具及其说明/许可证复制到可执行文件旁的 `tools/ffmpeg/`。当前工具要求 Windows 64 位，不等同于 Qt 应用本身的 32 位架构。

`scripts/package-portable.ps1` 默认读取 `build/release/`，先核对 `AppInfo.h` 与 EXE 版本，再将 Release 应用、Qt 运行库与声音插件、音频工具、MTP 读取脚本与 64 位 WPD 上传 helper和许可说明打包到 `dist/光剑曲谱制作*/` 下的新目录，入口重命名为 `LightsaberMusicalScoreCreation.exe`，同时创建空 `projects/`；完整目录另压缩为 Windows ZIP 交付。正式便携包见 [v0.4.0 Release](https://github.com/Vae-x/Lightsaber-Musical-Score-Creation/releases/tag/v0.4.0)，本地产物保留在忽略的 `dist/` 中，每次打包使用新的目录。Debug 构建仅用于开发，便携交付使用 Release。

测试源码包含 `tests/core_tests.cpp`、`AudioServiceTest.cpp`、`MainWindowTest.cpp`、`SongExporterTest.cpp`、`MtpImportTest.cpp`、`MtpExportTest.cpp`、`WorkspacePathsTest.cpp`、`AiSettingsTest.cpp`、`CodexAccountTest.cpp`、`SettingsDialogTest.cpp`、`AiRecognitionTest.cpp`、`AiTextTransportTest.cpp`、`AiGenerationTest.cpp`、`AiGenerationPageTest.cpp`、`GeneratedChartTest.cpp` 和 `DiagnosticLogTest.cpp`。测试媒体由 `GenerateAudioFixtures.ps1` 自建，用户曲谱样本留在本地。核心测试检查原样导出、修改合并、保护、恢复与 ZIP 路径；开场缓冲测试核对导出音频与物件的同步后移；音频测试需要有效声音设备；界面测试使用真实控件事件和轨道画面断言；MTP、默认工程路径和设置连接分别保留独立测试。AI 测试覆盖协议异常与恢复通知、音乐特征和动作校验、分段生成与有限修复、手动续跑、分析复用、离页进度保留及整谱应用的原子撤销；日志测试检查过滤、轮转、过期、并发、导出和写入失败。

新的编译输出使用 `build/debug/`、`build/release/`，其他验证使用 `build/` 下的专用目录，不新增根目录 `build-*`。此前的 `build-audio-test`、`build-audio-tools`、`build-device-inspect`、`build-integration-check`、`build-release`、`cmake-build-layout-check` 和 `build-branding-check` 集中归入 `build/archive/`，保留文件供追溯。

旧 CMake 缓存记录原绝对路径，只作为历史产物保存；重新构建使用新配置的 `build/debug/` 或 `build/release/`。已有 CLion `src/cmake-build-debug/` 不参与此次迁移，仍按原工作配置使用。`build/`、IDE 用户配置和本地环境文件由 `.gitignore` 排除。

默认工程保存到源码根或便携根的 `projects/<歌名>/project.lmsc`，入口旁边存放原资源、原媒体与恢复快照。程序目录无写权限时使用用户文档中的 `光剑曲谱制作/工程/`；每个工程单独建目录，避免只移动入口而遗漏资源。仓库 `projects/` 仅提交 `.gitkeep`。

空目录中的 `.gitkeep` 用于让 Git 保留目录；加入真实文件后可以移除该占位文件。

## 设备传输与歌曲导出

导入服务只读扫描两处游戏根目录，支持分类树。导出服务负责 Windows WPD 传输，64 位 C# helper 源码与构建脚本在 `scripts/`，编译产物位于 `build/` 并部署到程序旁的 `tools/mtp/`，不进入 Git。Qt 编辑器保持原工具链，不需要更换主框架。

电脑歌曲输出集中在所选目录的 `光剑曲谱制作/<歌名>-by光剑曲谱/`，同名追加编号。工程内部 `assets-*`、`source-*` 保持现有引用和恢复兼容；正式导出合并编辑状态后可手动复制或仅新增到设备分类目录。设备上传失败或取消不自动删除残留目录。
