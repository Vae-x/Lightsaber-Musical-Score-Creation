# 光剑曲谱制作使用说明

更新日期：2026-10-02，适用于 v0.3.0 及当前源码开发版。AI 整曲生成是源码开发版新增功能，已发布 v0.3.0 包仍保留原发布内容。此前 v0.2.0 的测试记录见更新说明。用户已确认导出歌曲在星穹绿洲和光之乐团中可以工作，同时反馈开头约 1 秒物件不显示；新增开场缓冲、AI 曲谱手感与 Windows 10 兼容仍须分别验证。详细证据见 [首版需求与架构](首版需求与架构.md)。

## 启动与文件

从 [v0.3.0 Release](https://github.com/Vae-x/Lightsaber-Musical-Score-Creation/releases/tag/v0.3.0) 下载完整 Windows 便携包并解压，在 Windows 64 位上双击 **`LightsaberMusicalScoreCreation.exe`**。同目录需要 Qt 运行库、声音/平台插件、`tools/ffmpeg/` 音频工具和 `tools/mtp/` 设备读取脚本；保留这些文件的相对位置。基础编辑与音频转换无需安装 Python、Qt 或 FFmpeg，可离线运行；AI 模型读取和账号授权需要网络，Codex 账号方式还需本机安装官方 Codex CLI。本机打包产物保存在 `dist/`，不随源码仓库提交。

**编辑工程**用于保存继续制作所需的资源与编辑状态；**导出的歌曲文件夹**用于复制到头显。导出请选择一个新的电脑目录，保留原始歌曲与工程，之后仍可继续编辑。

## 主题、AI、网络与关于

v0.3.0 已包含以下功能，旧 v0.2.0 包不包含这些功能。设置和 AI 识别直接集成在主窗口，通过左侧导航切换，不另开设置窗口。导航依次是“曲谱编辑、AI 识别、外观、大语言模型、账号授权、网络、关于”。菜单“设置 → 外观设置”或 `Ctrl+,` 直接切换到外观页。

左侧导航默认收起，仅显示图标。点击三横线按钮可展开文字，也可再次收起；悬停图标可查看名称，上下方向键可切换页面。展开、收起和切换页面都会保留当前曲谱、选中物件、播放位置及未应用的设置输入。返回“曲谱编辑”可继续原来的工作，导入、音频处理、编辑、保存和导出功能沿用已有流程。右侧设置按卡片分组，小窗口可滚动查看，保存与取消按钮固定在底部。

所有设置页共用三种操作：“应用”保存并留在当前页；“保存并返回”保存后回到曲谱编辑；“取消并返回”恢复最近成功保存的全部设置与主题，再回到曲谱编辑。单纯通过导航离开设置页会保留草稿，不会自动保存。

- **AI 分析与制谱（源码开发版）**：歌曲解码就绪后可分析音乐。新建歌曲可在开始前选择五档难度，并勾选方向方块、无方向方块、炸弹和墙，默认只生成方向方块。点击生成后，程序提取本地音乐特征，由所选模型编排整曲；完成后可试听候选谱，点击应用才替换当前新歌谱面，物件及难度可一起撤销。已有的本地节拍估计仍在曲谱编辑中使用。
- **外观**：选择浅色、深色或跟随系统，编辑面板与轨道预览一起切换。选择时立即预览；应用或保存后保留主题，取消恢复最近成功保存的主题。
- **大语言模型 / API Key**：选择 DeepSeek、Kimi、MiMo、OpenAI、通义千问或自定义服务。预设自动填入 API 地址，填入对应密钥后离开输入框会自动获取模型；也可点击“获取模型 / 检查连接”。选定模型后保存。读取失败时显示原因，并允许手动输入模型名。地址须包含服务要求的路径（通常为 `/v1`）；本机网关支持 loopback HTTP 地址，远程服务使用 HTTPS。
- **大语言模型 / Codex**：将使用方式切换为 Codex / ChatGPT 账号授权，再进入“账号授权”。本机有官方 Codex CLI 时自动查找，也可手动选择程序。点击“检查授权”复用已有登录，或点击“使用 ChatGPT 登录”在浏览器完成官方授权，随后获取账号模型并选择。授权和凭据续期由 Codex 管理。
- **网络**：默认“自动（系统代理）”，API 请求使用系统代理，Codex 沿用自身默认网络配置。选择“手动（HTTP 代理）”后填写 IP 或域名与端口，例如 `127.0.0.1`、`7890`；地址不带协议或端口。手动配置用于 API 请求和本程序启动的 Codex 账号服务，本机服务保持直连；切换后可重新获取模型检查连接。点击“应用”或“保存并返回”后保留配置；“取消并返回”恢复最近成功保存的配置。浏览器沿用自己的网络设置。
- **关于**：查看当前版本、作者 Vae-x 与许可，通过“打开项目主页”在默认浏览器打开 GitHub 项目。“查看 GPLv3 许可”在本页展开官方英文全文，可滚动阅读或收起；帮助菜单的“关于光剑曲谱制作”也进入本页。
- 各提供商的地址、密钥和模型独立保存。Windows API Key 由当前账户的 DPAPI 加密；应用设置保存在用户配置目录中，歌曲工程与游戏导出包不包含这些设置。账号登录保存在 Codex 自己的凭据存储中；取消设置不会退出已有账号。

基础编辑和音频转换仍可离线运行。AI 模型读取、分析及制谱需要网络，Codex 账号方式需要本机官方 Codex CLI，生成通道按 0.147.0 协议实现。模型只接收时间锚点、音乐特征与动作上下文；配置连接本身不会发起生成。生成失败或取消时原谱保持原状，只有完整通过校验的候选谱可应用。具体流程见 [AI 设置与自动制谱方案](AI设置与自动制谱方案.md)。

## 从 MP3 或 MP4 开始

1. 点击“新歌 · MP3 / MP4”，打开 MP3 或 MP4。在“创建新歌 · 音轨与裁剪”中填写歌曲名、作者 / 歌手、谱师，选择封面（可选）。MP4 仅提取声音；“提取音轨”可选择需要的音轨，没有音轨时会明确提示。
2. 输入“裁剪起点”“裁剪终点”。默认保留整首；用“试听所选片段”“停止试听”检查范围，确认后点击“转换并创建”。裁剪后时间零点就是片段起点，不会修改原文件。
3. 等待后台转换、PCM 解码与波形准备。转换为 Ogg/Vorbis，取消任务不会提交未完成的最终音频文件。
4. 在创建弹窗中选择简单 Easy、普通 Normal、困难 Hard、专家 Expert 或专家+ ExpertPlus，默认 Expert；只创建一张 **v2.2 / Standard** 空白谱。创建后也可在左侧“新歌难度”调整，已有音符保留；源码开发版的手动难度调整也作为单独一步撤销、重做。未选封面时生成默认封面，选定图片会居中裁成正方形。上述为通用文件标识，两游戏界面档位的准确对应仍需分别核验。
5. 自动估拍后勾选“节拍器”试听，检查拍线是否持续对齐重拍。必要时在“节拍校准”手动改“BPM”“第一拍时间”，点击“应用校准”；也可点击“重新估计节拍”或检查半速/倍速。自动估计不准仍能继续手动制作。
6. 在时间轴定位到需要的拍点，选择物件种类、颜色、切割方向，再在 4×3 网格放置；用属性区细调时间、位置和普通墙尺寸。
7. 保存编辑工程，检查“导出开场缓冲”后导出歌曲文件夹，再复制到所用游戏的目录进行头显验收。

新歌导出时，谱面文件随当前难度命名为 `Easy.dat`、`Normal.dat`、`Hard.dat`、`Expert.dat` 或 `ExpertPlus.dat`，`Info.dat` 引用同步对应。已有歌曲继续保留原谱面文件名。

左侧“导出开场缓冲”默认 **2 秒**，可调整为 **0～10 秒**；**0** 关闭缓冲。它只作用于新歌的游戏导出：音频前增加相应静音，方块、炸弹和墙的时间同步后移，原工程的音频、波形和编辑时间不变。例如原来 0.2 秒的方块，在 2 秒缓冲的导出歌曲中于 2.2 秒出现，并与后移后的声音保持对齐。已有谱不添加缓冲。

这个选项用于尝试规避游戏开头约 1 秒物件不显示的问题；开头物件可能缺少生成所需的预滚时间，具体原因尚未由游戏端确认。缓冲效果需要在星穹绿洲与光之乐团中分别复测，不能仅凭电脑导出校验认定已经修复。

“重新裁剪来源 · 新建空白谱”沿用工程保存的原媒体、音轨和范围，重新转换后创建**另一张空白新谱**。已有音符不随裁剪自动迁移；操作前会说明该行为，请先保存当前工程。原媒体和裁剪记录用于工程继续编辑，导出给游戏的歌曲目录仅使用当前转换音频。

## 编辑已有谱

1. 点击“导入歌曲文件夹”，在“电脑文件夹”页点击“选择电脑文件夹”，选择含 `Info.dat` 的歌曲目录；也可用“导入曲谱 ZIP”打开本地 ZIP。直接读取头显歌曲的方法见下一节。程序建立独立资源快照，导入不覆盖原曲谱。继续已有工程时用“打开编辑工程”选择 `.lmsc` 文件。
2. 选择要编辑的一张难度。已有其他难度和玩法保留；首版基础编辑范围是 Standard 双手玩法的 v2/v3 谱面。
3. 查看导入提示与保护原因。未知时间扩展、无法解释的关联或特殊玩法可能使当前难度只读；应保留原样，而不是猜测时间后写回。
4. 选择普通方块、炸弹和墙执行基础修改。多选命令同样受核心保护检查；关联弧线/链条或模组特效的方块可能无法修改、删除、镜像或复制粘贴。
5. 保存工程并导出到新目录。已有音频保持原资源；`.egg/.ogg` 差异按实际文件与唯一候选识别，不会自动统一改名或重新压缩。

已有曲谱的 BPM、第一拍偏移和变速数据保持原样，界面不允许手动改动这些参数。

## 从 PICO 头显读取已有歌曲

1. 通过 USB 连接 PICO Neo 3，解锁头显并允许 USB 文件传输。
2. 点击“导入歌曲文件夹”，打开“PICO 头显”页。软件读取下面两处目录，合并列出歌曲，并在歌曲名下标明“星穹绿洲”或“光之乐团”来源。同名歌曲仍是独立条目；连接后没有列表时点击“刷新头显歌曲”，按界面提示检查授权与目录。
3. 按游戏来源选中歌曲，点击“导入选中歌曲”。等待复制和文件检查完成，再选择难度进行编辑。有些歌曲目录名以 `.zip` 结尾，它们仍可作为头显歌曲目录导入。
4. 用“保存工程”保留到电脑的独立工程，随后按普通编辑流程操作。读取失败或中途断开时按提示重试；未完成的复制不会作为可编辑歌曲打开。

两处完整路径：

```text
星穹绿洲：此电脑\Pico Neo 3\内部共享存储空间\SoulTopia\BeatNote\Custom
光之乐团：此电脑\Pico Neo 3\内部共享存储空间\Android\data\com.StarRiverVR.LightBand\files\CustomMusic
```

这一入口只读取头显并复制到电脑临时缓存，不写回头显。电脑里的编辑工程与头显原歌曲分别保存；导出仍在电脑完成，再按“手动复制到 PICO Neo 3”中对应的游戏目标复制。Windows 文件选择器中的“此电脑”设备位置并非普通磁盘路径，应使用上述“PICO 头显”页导入。

## 时间轴、试听与选择

- 时间轴和网格使用同一拍数/秒数换算。节拍吸附决定放块和移动时的对齐精度。
- 时间轴滚轮缩放，Shift＋滚轮或右键/中键拖动浏览其他片段；点击空白时间位置或双击定位播放头。
- 点击物件选择，Ctrl 配合点击进行多选，空白处拖动框选；受保护对象显示锁和原因。
- 播放、暂停与定位按实际音频时钟同步轨道视图。慢放保持音高，第一次切换速度需要等待后台缓存准备。
- Shift＋左键拖动选择循环片段，然后启用循环，便于反复修改一段。节拍器用于校准，已有变速谱以识别出的分段时间模型为准。
- 轨道视图显示普通方块、炸弹与墙，可用于观察基础砍击方向和布局。弧线、链条、灯光与模组数据保留，但暂不专属绘制或模拟完整游戏效果。

## 保存与恢复

先点“保存工程”建立工程，默认建议 `projects/<歌名>/project.lmsc`；同名工程目录已存在时使用带编号的新目录，保存对话框中仍可更改位置和文件名。源码开发使用仓库根的 `projects/`，便携运行使用程序旁的 `projects/`；应用目录无写权限时回退到用户文档中的 `光剑曲谱制作/工程/`。

旁边的 `assets-*` 是原始资源快照，`source-*` 保存新歌原媒体，`autosave.lmsc` 是自动保存恢复快照；它们需要和工程入口一起保留、移动。每份工程放在独立目录，不要只带走 `.lmsc` 文件。

首次保存后，每 30 秒自动保存未保存的改动；用“打开编辑工程”重新打开 `.lmsc` 时，根据提示选择是否恢复快照。

编辑操作支持撤销重做；批量修改如果碰到受保护内容，会报告原因，不应默默只改一部分。导出与工程保存分别进行，导出的歌曲目录不包含游戏成绩或收藏配置。

工程清单原子写入，导出完整歌曲目录也使用暂存后提交。保存与导出任务开始后等待完成，不在中途打断；音频转换、解码等任务可通过“取消任务”取消。

## 手动复制到 PICO Neo 3

1. 点击“导出歌曲目录”，选择电脑上的父目录；软件创建新的歌曲子目录，已有同名目录时自动使用新名称。
2. 通过 Windows 文件管理器连接头显，按游玩目标将整个歌曲文件夹复制到对应位置：

   ```text
   星穹绿洲：此电脑\Pico Neo 3\内部共享存储空间\SoulTopia\BeatNote\Custom
   光之乐团：此电脑\Pico Neo 3\内部共享存储空间\Android\data\com.StarRiverVR.LightBand\files\CustomMusic
   ```

3. 在对应游戏中检查歌曲是否显示，音频是否能播放，选定难度是否可游玩，拍点和砍击方向是否合理。
4. 新歌重点检查开头物件：默认 2 秒缓冲时先有静音，再开始原来的音乐与物件。分别记录两个游戏的结果，需要时调整缓冲秒数后重新导出到新目录。已有谱的少量修改，以及 MP3、MP4 新建谱应分开验收。

用户已确认本轮修改前的导出歌曲在两个游戏中都可以工作；新增缓冲和 AI 自动制谱的实际手感仍须分别在头显复测，文件格式校验不能替代游玩。编辑器不会写入头显原文件。APK 在后续阶段考虑。

## 关于与协议

在“帮助”菜单点击“关于光剑曲谱制作”，切换到主窗口的关于页，可查看当前版本和项目说明；点击“查看 GPLv3 许可”在本页展开 GNU GPL 第 3 版官方英文全文，再次点击可收起。旧 v0.2.0 包使用原来的关于入口。项目代码使用 GPL v3；Qt、FFmpeg 等第三方组件保留各自协议与来源说明，随便携包一起提供。

## 开发者补充

源码通过根目录或 `src/` 的 CMake 入口构建；当前使用 Qt 5.12.12 / MinGW 7.3。新构建使用 `build/debug/` 或 `build/release/`，旧构建与核验产物保留于 `build/archive/`；原 CLion `src/cmake-build-debug/` 保持原位。首次准备音频依赖运行 `scripts/setup-audio-tools.ps1`，该脚本下载固定 Windows x64 LGPL shared 构建并检查 SHA256 与 Vorbis 编码器。依赖版本、许可和公开发行前需要整理的材料见 [音频工具说明](../third_party/ffmpeg/README.md)。

Release 编译完成后，`scripts/package-portable.ps1` 在 `dist/` 创建新的便携目录，携带 Qt 运行库、声音插件、FFmpeg/ffprobe、MTP 读取脚本、项目 GPL 与第三方许可说明；完整目录另压缩为 Windows ZIP。只有开发者准备依赖或重新打包需要这些脚本；普通使用者直接解压完整便携包。

`tests/GenerateAudioFixtures.ps1` 生成自制 120 BPM 的 MP3、双音轨 MP4 和无音轨 MP4，生成数据放在忽略的构建目录，不包含用户歌曲。`AudioServiceTest` 使用这些文件验证音频流程；实际播放测试需要有效的 Windows 声音设备。
